## Upgrading from 1.x to 2.0.0

Version 2.0.0 renames the theme, so WordPress treats it as a new theme in a new folder.

1. Upload `abrahamic-2.81.0.zip` (or any 2.x package) under Appearance > Themes > Add New > Upload Theme. It installs to `wp-content/themes/abrahamic/`.
2. Activate **Abrahamic**. Saved settings are copied from `ar_options` to `abr_options` automatically.
3. Check Appearance > Abrahamic and confirm the colour scheme, newsletter and social values.
4. Site Editor changes are stored against the theme slug and do not carry over. If the front page, header or footer was edited under 1.x:
   - switch back to "Abrahamic Religions" temporarily;
   - in Appearance > Editor, open each edited template or part and copy its blocks;
   - switch to Abrahamic and paste them into the same template or part.
5. Navigation menus created in the Site Editor are stored separately and remain available in the Navigation block's menu picker.
6. Once satisfied, delete the old theme under Appearance > Themes.
7. The legacy option row stays in the database for rollback. Remove it when no longer needed:
   ```
   wp option delete ar_options
   ```
8. Any custom CSS or code that targeted `ar-` classes, `ar_` functions or `[ar_…]` shortcodes must be updated to the `abr` prefix. See `ssot.md`, section 2.

## Release checklist

1. Update every version location listed in `ssot.md`, section 3.
2. Add the release to `changelog.md` and to the `== Changelog ==` section of `readme.txt`.
3. Update `ssot.md`: current version, release date, and any changed identifiers, tokens, breakpoints, settings or decisions.
4. Update this file: move delivered roadmap items out, add new debt, and add upgrade steps if anything breaks compatibility.
5. Update `readme.md` where structure, requirements or behaviour changed.
6. Lint every PHP file (`php -l`) and every script (`node --check`).
7. If starter content changed, add the new items with a new `since` value, raise `ABR_SEED_VERSION`, and update the inventory in `ssot.md`, section 12. Never rename an existing seed key.
8. Confirm the package holds the eight Sabon files in `assets/fonts/` and that Tools > System information reports "Bundled (8 files)".
9. Render the front page at 320, 390, 768, 1024, 1280 and 1440 pixels; confirm no horizontal overflow and a single-row header; open and close the overlay menu on phone and tablet widths.
10. Run the seeder on a fresh WordPress install, crawl the site, and confirm: every internal link returns 200; one `h1`, a unique title and a unique description of 130 characters or fewer on every page; a canonical address and breadcrumbs on every inner page; valid structured data; robots.txt and every sitemap address; a 404 status on the 404 page. Repeat on a site upgraded from the previous release and confirm the earlier addresses redirect.
11. If `assets/images/logo-mark.svg` changed, regenerate `logo.png`, `icon-192.png`, `apple-touch-icon.png` and `favicon-32.png` from it, and refresh `screenshot.png`.
12. Package the `abrahamic/` folder as `abrahamic-x.y.z.zip`.
